## 01  项目目标与边界


### 1.1 项目目标

- 构建支持四个期货品种独立参数、双向开平仓、实时触价触发、夜盘/日盘连续运行的桌面端自动交易系统。
- 以柜台回报为账户及持仓状态核对依据，完善重启恢复、人工交易识别、重复下单保护和限额风控。
- 提供策略主控、实时监控、系统设置三标签页，实现账户、持仓、权益、K 线、日志与通知的完整操作闭环。
- 形成可自动测试、可回放、可追责、可扩展的工程化项目，而非仅能运行的策略脚本。

### 1.2 本期交付范围

范围内：原始清单的 46 项功能、策略与账户持久化、最小审计日志、CTP 仿真联调、关键场景自动化测试、安装部署与恢复操作文档。

范围外（须另立需求）：跨券商统一资金池、Web/移动端、云端高可用集群、行情付费采购、策略收益优化承诺、交易所特殊席位或极低延迟高频系统。


### 1.3 约束与假设

- 一个 V7 策略实例默认归属唯一柜台账户；“多账户管理”先实现配置、登录与安全切换，不默认支持多个账户在同一进程并发下单。
- 四品种是首期策略实例数量；合约代码使用交易所唯一标识进行解析，不通过仅品种中文名称猜测实际合约。
- 系统需区分自然日、CTP TradingDay、夜盘交易时段；交易日切换标准及例外在需求评审时确认。
- 可用资金、保证金、手续费等字段受柜台与适配层限制；缺失时明确标注“估算/不可得”，不得静默伪装为柜台实测。

## 02  技术基线与系统架构


### 2.1 已核查的代码事实


| 检查点 | 代码事实 / 对实施的影响 |
| --- | --- |
| 框架仓库 | Yoruto/vnpy 是官方 vnpy/vnpy 的 Fork；master 在 c6e231c，vnpy/__init__.py 声明 4.5.0。 |
| 核心引擎 | MainEngine、OmsEngine、EventEngine 提供报撤单、行情与账户/持仓/成交事件；可直接作为 V7 基座。 |
| 交易数据模型 | TickData 使用 high_price/low_price；OrderRequest 带 reference；AccountData 基础字段不足以覆盖全部 V7 财务面板。 |
| 外部扩展 | CTP、CTA 策略、风控属于相互独立的仓库/安装包；必须锁定兼容版本并做集成验证。 |
| 图形组件 | 现有 PySide6、pyqtgraph、vnpy.chart 和 QSettings 可复用；定制三标签页需单独开发。 |
| 兼容性 | pyproject.toml 支持 Python 3.10+ 并固定 PySide6 6.8.2.1；建议先使用可兼容 CTP 的 64 位 Python 环境。 |


### 2.2 分层架构


| 层级 | 建议模块 | 核心职责 |
| --- | --- | --- |
| 接入层 | vnpy_ctp / MainEngine / OmsEngine | 行情接收、交易柜台请求与回报、合约资料、订单与持仓缓存。 |
| 策略层 | V7StrategyEngine / SignalEngine | 四品种参数、六类动作、互斥过滤、H/L 触发、夜盘延续。 |
| 风控层 | RiskCoordinator / TradingCalendar | 日内净亏、可用资金、风险度、单日报单、收盘前限制与异常冻结。 |
| 执行层 | OrderExecutor / OrderStateMachine | 交易意图、报撤单、平今平昨、部分成交、超时核对、幂等。 |
| 核对层 | AccountAdapter / ReconciliationService | 柜台账户扩展字段、持仓同步、人工交易检测、恢复状态。 |
| 数据层 | SQLite + 配置 JSON + 审计事件日志 | 权益快照、订单/成交、参数模板、交易日状态、通知记录。 |
| 展示层 | PySide6 Desktop + 图表 | 策略主控、实时监控、系统设置、托盘、通知与导出。 |


### 2.3 关键数据与控制流程

行情 Tick → 合约/时段验证 → H/L 与交易信号计算 → 互斥过滤 → 开仓限额与账户风控 → 生成唯一交易意图 → 报单 → 订单/成交/持仓回报 → 落库与界面刷新。

恢复流程：启动 → 网关连接与合约加载 → 查询账户、活动委托与持仓 → 重建交易日上下文 → 对比本地持久化状态 → 一致则启用交易；不一致则保持“只核对/禁新开”并提示人工处理。

建议交易服务与图形界面采用进程隔离（RPC/事件转发），并以交易服务为唯一报单入口。若首期资源受限，可先同进程分模块，但必须保持模块接口可迁移并验证关闭窗口最小化到托盘。


### 2.4 建议仓库结构

v7_trader/{core: strategy.py、signal.py、risk.py、execution.py、recovery.py、session.py；adapters: ctp_account.py；storage；ui；notifications；config；tests}。上游 vn.py 核心只允许必要的、经代码审查的兼容修复，不放入 V7 业务条件分支。

| 名称 | 关键键或字段 | 用途 |
| --- | --- | --- |
| strategy_config | account_id、vt_symbol、参数版本 | 四品种参数配置与模板应用记录。 |
| order_intent | intent_id、trade_day、action、vt_orderid、state | 防止重复报单、重启后追踪未完成交易。 |

## 03  分阶段实施计划（16 周基准）

本计划为工作量估算而非交付保证。以第 1 周完成需求启动为 T0；关键业务规则、CTP 接入资格及人员投入需要满足前提，否则顺延。


| 阶段 / 周次 | 交付重点 | 阶段验收门槛 |
| --- | --- | --- |
| P0 · W1–W2 需求冻结与基础联调 | 逐项规则确认；技术基线锁定；CTP 仿真接入；行情、资金、订单、成交、持仓闭环；核心数据字典。 | 能在仿真账号发送、撤销及接收订单，完成账户/持仓查询；输出规则签字版。 |
| P1 · W3–W5 策略核心 | 四品种参数；双向六动作；Tick 高低价；H/L 去重；互斥过滤；价格和交易时段模型。 | 历史 Tick 回放的信号可复现；不存在同键重复交易意图。 |
| P2 · W6–W9 风控与安全闭环 | 动态手数、净亏与报单限制；移动止盈；强平；夜盘延续；手动识别；重启恢复；订单状态机。 | 15 类以上异常场景回放；实盘级故障场景测试通过；第 9 周完成 MVP。 |
| P3 · W10–W12 主控与监控界面 | 三标签页；账户/持仓实时面板；权益快照与 CSV；1 分钟 K 线；日志显示/筛选/导出；合约检索。 | 每个面板可对照柜台或数据日志复核；典型运行期间 GUI 不阻断交易进程。 |
| P4 · W13–W14 配置与运维 | 参数模板、多账户安全切换、声音/钉钉、定时启动、自动重连、托盘、主题、快捷键、CSV 导入/导出。 | 断线重试不重复报单；多账户切换具备未完单保护；配置重启后可恢复。 |
| P5 · W15–W16 联调验收与发布 | 全功能回归、连续仿真运行、性能与故障注入、运维手册、升级回滚、安装包、版本标签。 | 重大/高风险缺陷清零；回放与仿真记录完整；发布评审通过。 |


### 3.1 依赖顺序与并行开发

- P1 必须依赖 P0 的交易日规则、交易公式与 CTP 数据字段定义；否则策略信号测试没有客观标准。
- P2 的订单状态机和核对层在 P1 期间同步设计、P2 集成；优先于高级界面功能。
- P3 界面设计和数据视图可从 W3 开始并行，但最终绑定以 P2 稳定的事件接口为准。
- P4 通知、主题、托盘等外围功能可提前开发，但不能占用风控和恢复的测试资源。
- P5 的仿真验收要求经历可代表夜盘/日盘的真实交易时段；若节假日或无测试环境，需要调整验收窗口。

## 05  核心交易规则与风控专项设计


### 5.1 信号与价格口径：先验证，后冻结


| 规则主题 | 建议研发处理 | 业务需确认 |
| --- | --- | --- |
| 高低价与 K 线 | 记录 Tick.high_price/low_price、最后价及每根1分钟bar的起止；触发统一由 SignalEngine 判定。 | H/L 是交易日统计高低点还是区间高低？同根 bar 的再次触发如何复位？ |
| 互斥过滤 | 将原式原样配置为判定条件并做参数边界测试，记录“禁多/禁空”原因。 | 四个比较价格的精确定义；等于时行为；过滤优先级。 |
| 移动止盈 | 状态：未激活 → 激活 → 新高(低)更新 → 回撤触发 → 待成交。 | 80% 是止盈点数还是盈利额；回调10%相对最大浮盈或价格？ |
| 收盘管理 | 分品种交易时间，预设20秒触发，不保证成交；管理活动委托及平仓重试。 | 20秒能否配置；未成交是否加价追单、几次、何时停止？ |
| 夜盘延续 | 每笔保存“被动平仓原因”，仅指定原因及下一日条件成立才重新开仓。 | “被动平仓”包括哪些情况？日盘次日定义和最多重开次数？ |
| 报单次数 | 交易意图、每次实际报单请求和柜台 OrderData 独立计数。 | 拒单、撤单重报和强平是否计入每日限额？ |
| 单日累计净亏 | 按账户+交易日+品种记账；触及净亏限额锁定新开仓。 | 止损偏移×倍数如何换算货币；手续费、人工单是否计入？ |


### 5.2 仓位计算与账户风险

建议采用“双重上限”：资金可承受最大保证金手数、单笔预期损失上限手数，两者取较小值，同时考虑交易所最小手数、账户当前风险度、最大总仓位和锁定的剩余报单次数。详细阈值由用户确认，不预设盈利能力。

示意公式（仅工程框架，非既定业务公式）：允许开仓手数 = max(0, min(按保证金预算可开手数, 按单笔风险预算可开手数, 单品种/账户仓位上限))。当费用、保证金率或柜台账户数据缺失时默认不新增仓位。


### 5.3 幂等报单及状态机

每次策略动作生成唯一 intent_id（账户+合约+方向+动作+交易日+触发bar+触发序号），先落盘后发单。状态示例：CREATED → VALIDATED → SUBMITTED → ACKNOWLEDGED → PARTIAL/FILLED 或 REJECTED/CANCELLED；断线进入 UNKNOWN 待核对，而不是自动补发。

对交易所平今/平昨：通过 OffsetConverter 生成实际委托，并核查交易所、合约、可平量。每个子委托继承同一交易意图，防止拆单之后重复执行。


### 5.4 故障时默认操作


| 场景 | 默认限制 | 恢复条件 |
| --- | --- | --- |
| 行情超时/无有效价格 | 暂停新开与基于失效行情的策略单；人工可见告警。 | 有效 Tick 恢复 + 时戳校验。 |
| 网关断线 | 暂停新开；记录所有 UNKNOWN 活动订单。 | 重连并完成柜台订单、成交和持仓核对。 |
| 发现人工成交或额外持仓 | 冻结受影响的合约自动开仓；不假设策略仓位。 | 确认归属及手动处置或安全映射。 |
| 累计净亏/报单阈值 | 暂停新开；保留风控允许的平仓和撤单。 | 下一交易日按确认规则重置、或授权解锁。 |
| 收盘前平仓未完成 | 进入 CLOSING/WAIT_SYNC，告警、记录剩余量。 | 柜台回报核对完成或人工确认异常。 |


## 06  测试策略与验收标准


### 6.1 测试层级与覆盖


| 层级 | 关键用例 | 建议执行方式 |
| --- | --- | --- |
| 单元测试 | 参数校验、六种动作、H/L、互斥过滤、止盈回撤、资金手数、交易日归零 | pytest + 确定性 Tick 序列；核心逻辑目标覆盖率≥85%。 |
| 集成测试 | OMS/CTP 适配、报单撤单、平今平昨、手续费、账户/持仓快照 | FakeGateway + SimNow/券商仿真；比对柜台流水。 |
| 回放及故障注入 | 重复 Tick、重复成交、部分成交、拒单、撤单失败、断线重启、收盘未平 | 预制事件序列，输出预期/实际状态差异报告。 |
| GUI 及性能 | 5000+ 合约检索、1分钟K线、5秒权益采样、日期过滤与导出、托盘 | 自动化 GUI 冒烟 + 人工验收；界面卡顿不阻塞交易。 |
| 连续仿真 | 日盘/夜盘跨时段、自动重连、配置保留、日志存储增长 | 建议至少覆盖10个有效交易日或双方认可的完整交易窗口。 |


### 6.2 必过的高风险用例

- 同一根 K 线重复触发；策略重启/行情重放不重复下单；部分成交后处理冻结手数。
- 报单请求成功但本地回报延迟；断线时柜台仍然成交；恢复后 UNKNOWN 订单核对。
- 夜盘跨自然日、高低价重置、交易日归属、日盘重开条件。
- 已有人工持仓，策略恢复时不能冒认并自动平仓；账户切换不能沿用前账户未完成委托。
- 到达净亏/报单限额后允许风险平仓；资金及保证金数据无效时禁止新增仓位。
- 收盘前平仓未成交、撤单失败与交易所时段限制；界面关闭到托盘后交易保持服务化运行。

### 6.3 发布验收门槛

- 46 项需求逐条标记“通过/未通过/阻塞/经批准变更”，所有 P0/P1 关键风控项均需通过。
- 严重级别 P0（资金安全、方向错误、重复开仓）和 P1（持仓失配、丢成交）缺陷数量为 0。
- 具有可复现回放样本、订单/成交与策略事件日志，版本和配置快照可以关联。
- 完成至少一次断线恢复、一次进程重启恢复、一次跨交易时段的端到端验证。
- 生成安装包、依赖锁定表、变更记录、用户操作手册、故障应急与回滚文档。
> 重要提示  仿真验证通过不能视为真实交易一定成交，更不能构成盈利保证。是否转实盘应另外进行账户授权、风险限额检查和小仓位验证。
